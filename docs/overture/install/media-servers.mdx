# Media servers

Overture works with any number of Plex, Jellyfin and Emby servers at once.
Name them in `MEDIA_SERVERS`, the lead first, and configure each with
variables named after it:

```bash
MEDIA_SERVERS=Plex,Jellyfin

MEDIA_SERVER_PLEX_TYPE=plex
MEDIA_SERVER_PLEX_URL=https://192.0.2.10:32400
MEDIA_SERVER_PLEX_API_KEY=<token>

MEDIA_SERVER_JELLYFIN_TYPE=jellyfin
MEDIA_SERVER_JELLYFIN_URL=http://192.0.2.11:8096
MEDIA_SERVER_JELLYFIN_API_KEY=<key>
```

A name starts with a letter and holds letters, digits and single underscores;
it is how the server is shown, with underscores as spaces (`Living_Room`
shows as "Living Room"). Each server takes these variables, with
`MEDIA_SERVER_<NAME>_` in front:

| Variable           | Required | Description                                                                        |
| ------------------ | -------- | ---------------------------------------------------------------------------------- |
| `TYPE`             | Yes      | `plex`, `jellyfin` or `emby`                                                       |
| `URL`              | Yes      | Server address with protocol, port and any base path                               |
| `API_KEY`          | Yes      | Server token or API key                                                            |
| `VERIFY_TLS`       | No       | `true` by default; set `false` only for a self-signed certificate                  |
| `PATH_MAP`         | No       | Where Overture sees the server's media folders; see [Path maps](#path-maps)        |
| `COLLECTIONS_PATH` | No       | Jellyfin only: its collections directory, mounted into Overture, for BoxSet themes |

Every server should prefer local assets, so the files Overture writes beside
your media are the ones it shows.

1. Create a key under **Dashboard -> API Keys**.
2. Set `TYPE=jellyfin`, `URL=http://<server>:8096` and `API_KEY=<key>`.
3. In each library, keep local images ahead of online image fetchers.

To write themes for Jellyfin collections (BoxSets), mount Jellyfin's
collections directory into Overture and name it in `COLLECTIONS_PATH`, such
as `MEDIA_SERVER_JELLYFIN_COLLECTIONS_PATH=/jellyfin/config/data/collections`
for a mount at that path. Without it, Jellyfin collections get no theme while
other servers still do. A managed collection whose BoxSet folder has no theme
gets its theme on its next sync.

Jellyfin lists a collection's members only to a user, so Overture asks for
them as one of its administrators; keep at least one.

## Path maps

Overture writes artwork and themes into the media folders the servers report,
so it must see those folders at the same paths. When Overture's container
mounts your media at the paths every server reports, as when all of them use
`/media/movies`, `PATH_MAP` is not needed.

When a server sees the folders at another path, for example in its own
container or on Windows, map the server's path to Overture's:

```bash
MEDIA_SERVER_JELLYFIN_PATH_MAP=/data/movies=/media/movies,/data/tv=/media/tv
```

Each entry is `server_path=local_path`, separated by commas; the longest
matching server path wins, and Windows paths such as `D:\Movies` work too.
Paths no entry matches are used as the server reports them. Sync matches a
title across servers by its folder as Overture sees it, so every server's
paths must lead to the same folder once mapped.

## Several servers

Overture keeps one library across every server: a title several servers hold
is one title, with one set of choices and files, and a copy on each server.
Sync matches a server's item to a title by the copy it already knows, then by
its folder, then by its IMDb, TMDB or TVDB ID.

- **The lead server**, the first in `MEDIA_SERVERS` that lists a title, gives
  its title, year, genres and other details. What each server holds of its
  own, its library, labels, play state and rating, stays with its copy.
- **Files** are written once, in the title's folder, under every name its
  servers read, such as both `Season01.jpg` and `poster.jpg` for a season;
  see [Files](../features/files.md).
- **Uploads and audits** reach every server holding the title. The Server
  audit compares each server on its own and lists the server with each
  result.
- **Libraries** are named after their server wherever you choose them, such
  as "Plex · Movies". Filters, collections and schedules take libraries from
  any server.
- **A server that does not answer** is left out of that sync, with a notice
  naming it; the others sync as usual, and nothing it holds is removed.

### Collections on several servers

A collection may span libraries on any server: each server gets its own copy,
kept alike. Options a server cannot keep give way on that server only:

- A smart collection is smart on Plex; other servers get a regular collection
  of the members Overture evaluates from the same criteria.
- Visibility, collection mode, Home order and filtering apply to Plex copies
  only.
- An order a server cannot sort by keeps that server's default order.

See [Collections across libraries](../features/collections/across-libraries.md).

## Add, remove or replace a server

Change `MEDIA_SERVERS` and restart; Overture keeps your choices, files and
collections throughout.

- **Adding a server**: its first sync matches its items to your titles and
  lists its libraries and collections.
- **Removing a server**: its libraries are hidden, and titles only it held are
  hidden with them. Collections it held that Overture does not manage are
  forgotten; managed collections keep their settings for that server. Sync
  schedules skip its libraries, and Server audit results are cleared.
- **Bringing a server back**, or renaming one: a server at the same type and
  address picks up where it left off, its libraries and copies included.
- **Replacing a server**: remove the earlier one and add the new one. Its
  first full sync moves collections, sets and schedules from a library no
  server lists any more to the library its titles are now in, and a managed
  collection takes over the new server's collection of the same title in that
  library instead of making a second one. Sync once with every library before
  editing collections.

## No media server

Set `MEDIA_SERVERS=none` to curate OvertureDB without a media server. Sync,
Audit and Collections are hidden, the sidebar opens on OvertureDB, and nothing
reports a server as down.

| Feature                                       | With `TMDB_API_KEY` | Without |
| --------------------------------------------- | ------------------- | ------- |
| Browse the catalog, drafts, export and issues | Yes                 | Yes     |
| Pasted art URLs and YouTube theme search      | Yes                 | Yes     |
| TMDB art candidates and TMDB-only titles      | Yes                 | No      |

## How each server differs

Overture evens out most differences, but some follow from the servers
themselves:

| Behaviour                                  | Plex                                                                                      | Jellyfin and Emby                                  |
| ------------------------------------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Season poster file name                    | `Season01.jpg` in the season folder                                                       | `poster.jpg` in the season folder                  |
| Deleting artwork through the API           | Not possible; delete the local file and Plex shows its agent's art after the next refresh | Supported                                          |
| Smart collections                          | Supported, evaluated by Plex, with labels for conditions Plex has no filter for           | Not available; Overture evaluates every collection |
| A collection across several libraries      | One collection in each library, kept alike by Overture                                    | One collection holding every library's members     |
| Separators (empty heading collections)     | Offered                                                                                   | Not offered                                        |
| Visibility, collection mode and Home order | Supported                                                                                 | Not available                                      |

See [Files](../features/files.md) for every file name and
[Collections across libraries](../features/collections/across-libraries.md).
